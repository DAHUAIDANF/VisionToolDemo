# 训练功能：小样本图像分类训练（纯 C# CNN，导出 ONNX 可商用）

> 本功能让 **VisionToolDemo** 在软件内完成「小样本图像分类模型」的训练闭环：
> 选择图片目录 → 训练（纯 C# 卷积神经网络，无第三方训练框架）→ 验证 → 导出 **ONNX**
> → 由既有「深度学习推理」算子直接加载推理。全链路开源免费可商用（MIT 自研实现，
> 不引入 AGPL 组件）。

---

## 一、入口

主窗口左侧导航新增「**训练**」页（「记录」与「设置」之间）：

1. **选择训练集目录**：每个子文件夹 = 一个类别，子文件夹名即类别名（建议英文/数字，
   如 `red/`、`blue/`）。点「浏览…」选目录，点「扫描统计」查看类别与样本数。
2. **训练参数**：
   - 输入边长：32 或 64（正方形；必须为偶数；越大越慢、细节越好）
   - 训练轮数：默认 100（小样本 100~300 常用）
   - 学习率：默认 0.003（loss 震荡就调低到 0.001）
   - 批大小：默认 8（样本总数小时可保持 4~8）
   - 随机种子：默认固定，可复现结果
3. **开始训练**：后台线程执行，日志实时回流，可随时「停止」（当前轮结束后生效）。
   训练完成显示「第 N 轮 / 准确率 / loss」。
4. **验证一张图…**：选任意图片立即预测，显示各类别概率与预测类别。
5. **导出 ONNX…**：默认输出到 `程序目录\train_output\`（model.onnx + labels.txt），可自选目录。

---

## 二、训练集要求（小样本）

| 项 | 建议 |
|---|---|
| 每类最少 | 2 张（少于 2 张训练直接报错） |
| 每类推荐 | 50~200 张（小样本效果最佳） |
| 类别数 | 2~16 |
| 支持格式 | png / jpg / jpeg / bmp / webp |
| 目录结构 | 训练集目录 / 类别子文件夹 / 图片文件 |

- 图片会被自动缩放/填充到「输入边长」正方形（RGB 浮点 0~1）。
- 类别不均衡会降低准确率，尽量每类数量接近。

---

## 三、导出后接入「深度学习推理」算子

在「视觉」页添加「深度学习推理」算子，参数区选择：

| 参数 | 取值 |
|---|---|
| 任务类型 | 0 = 分类 |
| 模型文件 | 训练导出的 `model.onnx` |
| 标签文件 | 同目录 `labels.txt`（每行一个类别名，顺序与导出一致） |
| 输入边长 | 与训练时的「输入边长」一致（如 32） |

模型协议：输入 `[1,3,S,S]` RGB 浮点 0~1，输出 `[1,类别数]` logits，推理端自动 softmax。

---

## 四、实现结构

| 文件 | 说明 |
|---|---|
| `Vision/Train/DeepTrainer.cs` | 纯 C# CNN：Conv(3×3,pad1)→ReLU→MaxPool(2) ×2 → Flatten → 全连接；Adam 优化、提前结束、可停止；`LoadFolder` 按子目录=类别加载；`TrainedModel.Predict` 单图预测 |
| `Vision/Train/TrainOnnxExporter.cs` | 自研 ONNX 导出器（手写 protobuf，opset13 / IR8）：节点图 Conv→Relu→MaxPool→Conv→Relu→MaxPool→Flatten→MatMul→Add，权重转置为 ONNX 约定，不依赖任何第三方导出库 |
| `Wpf/Views/TrainPage.xaml(.cs)` | 训练页面（目录选择 / 统计 / 参数 / 训练日志 / 验证 / 导出） |
| `Wpf/MainWindow.xaml(.cs)` | 左侧导航注册「训练」页 |

## 五、验证记录（本轮实测）

1. **Linux 反射冒烟 98/98 全绿**，含新断言：
   `训练器: 合成数据收敛+预测+导出ONNX`（合成 12 张红/蓝图，60 轮 lr=0.005，收敛 loss<0.25、准确率 100%、预测分类正确、导出字节有效）。
2. **Python 复核导出 ONNX**（onnx 1.23 + onnxruntime 1.29）：
   - `onnx.checker.check_model` 通过；
   - `onnxruntime.InferenceSession` 加载成功；
   - 红图 → red（概率 0.999）、蓝图 → blue（概率 0.999），与 C# `Predict` 输出**逐位一致（偏差 0.0）**。
3. 修复过程中定位并修正的 ONNX protobuf 字段号（手写编码易错点）：
   - `TensorProto.name = 8`（误写 1 与 dims 冲突，曾致 initializer 空名）
   - `AttributeProto.type = 20`、`ints = 8`（曾致 attribute 内容丢失）
   - `ValueInfoProto.type = 2`（误写 3 实为 doc_string，曾致 onnxruntime 拒绝加载）
   - `GraphProto.name` 必填非空
   - 冒烟合成样本布局由「交错 RGB」改为「NCHW 平面」，与 Forward / ONNX 输入协议对齐。

## 六、Windows 实机复测路径（Linux 无法跑 WPF/推理，需在 Windows 换包验证）

1. 用本包在 Windows 打开 `VisionToolDemo.sln`，`dotnet build -c Release`（需 net8 SDK）。
2. 运行程序 → 左侧「训练」页：
   - 建测试目录：`train_data/red/` 放 5~10 张红图、`train_data/blue/` 放 5~10 张蓝图；
   - 扫描统计 → 开始训练 → 验证一张图 → 导出 ONNX。
3. 「视觉」页添加「深度学习推理」算子 → 选导出的 model.onnx + labels.txt，
   输入边长设 32 → 载入一张红图/蓝图，确认分类正确。
4. 深度学习推理算子既有的 `test_models/mini_classifier.onnx`（随包微型测试模型）仍可复测。
